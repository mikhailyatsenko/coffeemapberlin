Type: research
Status: resolved

## Question

What do modern, well-regarded place-directory / map-listing sites (e.g. Google Maps place listings, Beli, The Fork, a specialty-coffee directory app if one exists) do differently from berlincoffeemap in: typography pairing, color palette use, card design, map+list layout, and filter/search placement? Capture concrete, screenshot-referenced patterns (not just opinions) that later tickets on this map can point to instead of relying on the agent's unaided taste.

## Answer

Looked at three live products via chrome-devtools MCP (desktop 1440×900 and mobile 390×844 viewports), plus the current berlincoffeemap desktop UI for a baseline. No specialty-coffee-directory app has a comparable list+map product; **European Coffee Trip** (europeancoffeetrip.com) is the closest domain match (curated specialty-coffee guide, Berlin page has 125 cafés) but its UI is a photo-grid catalog, not a live-synced map+list, so it's used as a contrast case rather than a pattern source.

### Google Maps (place search "coffee berlin", desktop + mobile)

- **Typography**: one sans-serif family (Google Sans/Roboto-derived) throughout — list, card, and map labels. Hierarchy comes entirely from weight and size (bold 16px place name, regular 14px secondary lines, small 12px meta), never a second typeface.
- **Color**: near-white/grey UI chrome; color is reserved for semantics only — red teardrop pins for POIs, green for "Geöffnet"/open status, blue exclusively for interactive/tappable text (links, "Zur Website", the accepted-filter pill outline). No decorative accent color on cards or chrome.
- **Card design** (list item, ~110px tall): thumbnail photo (fixed small square, left) + name (bold) + one line combining star rating, review count in parens, and a `·`-separated price band ("1–10 €") + category ("Café") + address, then an open/closed status line with closing time, then a row of plain-text amenity flags (✓ Speisen vor Ort, ✓ Zum Mitnehmen). Sponsored cards get an inline text ad block directly under the same card, visually identical weight, only labeled "Gesponsert". Everything needed to decide "is this worth a click" is legible without opening the card.
- **Place detail card** (after clicking a pin/list item): full-width hero photo strip (swipeable), name (large bold), rating+count+price+category on one line, then a row of 5 circular icon-buttons for primary actions (Route, Speichern/Save, In der Nähe, Send to phone, Share) — icon + one-word label under each, no text-only buttons competing for the same row. Below that: a one-line AI/editorial summary sentence, amenity checklist, then address/hours as separate rows with a leading icon each.
- **Map+list layout**: true split view on desktop — fixed-width list column (~380px) on the left, map fills the remainder, both always visible and mutually synced (hover/click a list row highlights the pin). On mobile, there is no split: the list is primary and full-width; the map is not shown by default, reached via a separate "map view" affordance, and clicking a result opens the place card as a new full-screen view (not an overlay on the map) with the map now a secondary panel below the fold.
- **Filter/search placement**: search box top-left, permanently visible. Directly under it, a horizontal scrollable row of pill-shaped filter chips (Preis, Bewertung, Öffnungszeiten, Alle Filter) — each a single tap/click to open a small popover, not a full-page filter screen. Applied filters visually distinguish by filling the pill (dark background) instead of outline-only.

### TheFork (restaurant discovery, Berlin listing, desktop + mobile)

- **Typography**: single geometric sans-serif (custom "Ambit"-style face) for everything, from the H1 down to card meta text. Bold weight only for the restaurant name and the numeric rating; everything else is regular weight. No serif or script accents anywhere, including on food-photography overlays.
- **Color**: near-black text on white, one brand accent (dark teal-green, `#1a5e52`-ish) used sparingly — primary CTA buttons ("SEARCH", time-slot chips), the active/selected filter pill, and the numeric rating badge. A separate, unrelated accent (light green) is reserved only for discount badges ("-30%"), so color itself carries meaning (brand action vs. promotional info) rather than being decorative.
- **Card design** (list item, ~180px tall): swipeable photo carousel (dot indicator) on the left third with badges overlaid directly on the photo (rank "Top50", "Insider" pill) and a heart/favorite icon top-right of the photo; right two-thirds: name (bold, large), address, then one line combining cuisine + average price (`Asian · Average price €20`); numeric rating (X.X out of 10, teal, bold, large) with review count below it in the far-right corner; a row of bookable time-slot chips at the bottom of the card with a discount badge under each. The card is dense but every element maps to a decision variable (worth it? affordable? can I book tonight?).
- **Map+list layout**: desktop is a true split (list ~45%, map ~55%, both live, synced — map pins show the same numeric rating badge as the list card, colored by whether a discount applies, so the map alone communicates quality+deal without opening a card). **Mobile is a toggle, not a split**: the map shrinks to a short static, non-interactic preview strip (~250px tall) between the page intro and the list, overlaid with a single pill button, "View on map", that presumably expands to a full-screen map (list becomes secondary). This is the clearest concrete pattern for "how do modern sites handle map+list on mobile without cramming both into the viewport": collapse the map to a teaser strip + explicit toggle button, rather than a permanent split or a bottom-sheet-only map.
- **Filter/search placement**: same "search bar + horizontal filter-pill row" pattern as Google Maps — Date/Time/Pers. as a grouped segmented control, then standalone pills (Special offers, Dinner today, Best rated, Cuisine, Neighborhood, Price, …) in a horizontally-scrollable single row directly below the search bar, always visible, no drawer needed for the common filters. Only "All filters" opens a fuller panel.

### European Coffee Trip (specialty-coffee directory, Berlin guide, desktop)

- **Typography**: one heavy-weight rounded sans for headings (H1 "Berlin, Germany" is very large, 700+ weight) against a lighter body weight of the same family for descriptions — again a single family, contrast from weight/size only, not a second typeface.
- **Color**: high-contrast two-tone brand identity — solid indigo/blue header band with white text and outlined-button CTAs, otherwise pure white page background and near-black text; color is used as a strong brand block (header, nav) rather than sprinkled through content.
- **Card design**: deliberately photo-first and image-heavy — full-bleed square/rectangular photo tiles in a 3-column grid, cafe name overlaid directly on the photo in bold white text with a drop shadow (no separate text card below), a small star-ribbon badge (premium-listing marker) in the top-left corner. No rating, no address, no category shown at grid level — clicking through is required, which trades information density for a stronger visual/editorial feel. This is a useful negative example: dense info-first (Google/TheFork) vs. sparse photo-first (ECT) are two legitimate but very different "modern" directions.
- **Map+list layout**: not a synced split at all — a static (non-list-synced) map with clustering sits above the fold, and the photo-grid list is a separate, independently-scrollable section below it. Clicking a cluster/pin does not highlight or scroll to a card. This is the weakest pattern of the three and is called out here specifically so later tickets don't cite ECT as a map+list model — cite Google Maps or TheFork for that dimension instead.
- **Filter/search placement**: none visible on the city-guide page itself beyond a top-level nav (Magazine / City Guides / Brew Guides / Awards); filtering happens by drilling into a different guide page rather than live filter controls on the same view.

### Baseline: current berlincoffeemap (desktop, https://3welle.com)

For contrast, the current site already does a true synced split (fixed-width list left, map right, clustering with counts) — structurally closer to Google Maps/TheFork than to ECT. Card content: square thumbnail, name, a 5-coffee-bean rating icon row (fixed value "5", not clearly tied to a numeric average), one neighborhood-tag pill, address, and two small square social-link icon buttons (Instagram, Google Maps) — no price band, no open/closed status, no category, no distance. Rating is shown as a full row of 5 filled bean icons regardless of place (visually implies every place is rated 5/5, which reads as decorative rather than informative next to Google's/TheFork's numeric-rating-plus-count pattern). Filter is a single funnel icon button next to the search box (opens an unseen panel) rather than the always-visible filter-pill row both reference sites use.

### Takeaways for later tickets

1. **Typography**: every reference uses exactly one sans-serif family and builds hierarchy from weight/size alone — no second "display" typeface anywhere, including in headings or photo overlays.
2. **Color**: accent color is functional, not decorative — reserved for CTAs, active/selected states, and one or two semantic signals (open/closed, discount). Backgrounds stay near-white/near-black; no reference site tints card backgrounds with the brand color.
3. **Cards**: the strongest info-first pattern (Google Maps, TheFork) always surfaces rating-with-count, category/price, and an open/availability signal at a glance, in addition to name/photo/address — more than berlincoffeemap's current card shows. The photo-first pattern (ECT) is a legitimate alternative but trades that information away.
4. **Map+list on mobile**: the concrete, actionable pattern is TheFork's — a short static map preview strip with an explicit "View on map" pill, not a permanent split and not a full-screen-map-by-default. Google Maps mobile instead makes the list the whole screen and treats the map as a separate destination.
5. **Filters**: a horizontally-scrollable row of filter pills directly under the search bar, always visible, filled/dark when active — used identically by both Google Maps and TheFork — is the concrete "modern" filter-placement pattern, versus berlincoffeemap's single funnel-icon button that hides all filter state.
